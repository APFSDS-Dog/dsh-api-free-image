## 一、30 秒看懂现状

- **一句话**：在 DSH 里，填了 API Key 就能用免费的 Kolors 模型出图。完全免费，不扣钱。
- **已正式发布**：npm 上有 `dsh-api-free-image@1.1.1`（latest），GitHub 上有源码与 tag。
- **防误扣费（物理防呆）**：模型 `Kwai-Kolors/Kolors` 写死在 provider 里（`src/providers/siliconflow.ts`）。
  - 工具的**入参里没有** `model` 参数，外部无法指定别的模型；
  - 但**真正发出去的请求 body 里一定带 `model: "Kwai-Kolors/Kolors"`**（抓包已实证），这是协议要求字段，不是可调参数。想换模型必须改源码。
- **假参数已全部删除**：`num_images`、`seed`、`output_format`、`batch_size` 等经实测全是服务端静默忽略的假参数，已在代码中彻底剔除（有抓包自检兜底，见 §五）。
- **本地限额拦截**：IPM=2（每分钟2张），IPD=400（每天400张）。超限本地直接拦截，**不发请求**。
- **多平台预留**：核心请求层已抽象出 Provider 概念，未来可接入其他平台的免费 API。

## 三、安装方式与当前状态

### 0. 三种安装方式，行为完全不同

DSH 里同一个插件**只允许一种安装方式**，并存会崩（见坑 1）。

| 方式 | 命令 | 装的是 | 改完源码后 |
|---|---|---|---|
| **npm**（推荐给普通用户） | `dsh plugin --profile desktop add dsh-api-free-image` | registry 上的正式版本 | 需重新发版 |
| **tgz**（发给朋友/离线） | `dsh plugin --profile desktop add "路径\dsh-api-free-image-1.1.0.tgz"` | 打包快照 | 需重新 pack + 重装 |
| **link**（本地开发） | `dsh plugin --profile desktop add "D:\Projects\dsh-kolors-plugi"` | 指向源码目录的链接 | `pnpm build` + 重启 DSH **即生效** |

图形界面等价操作：DSH → 左下角 **设置** → **插件** → **添加** → 填包名 / 选 `.tgz` / 选目录。

## 四、⚠️ 血泪避坑指南

### 坑 1：千万不要"重复安装"（会导致 DSH 崩溃）
**现象**：DSH 打开直接崩溃退出，日志报 `duplicate factory registration for "dsh-api-free-image"`。
**原因**：既用 `link` 链接了本地目录、又用 `tgz` 安装了包，DSH 会同时加载两份 UI，直接崩溃。
另一种同源情形：**在 DSH 运行期间重装插件**，旧 factory 没失效、bundle 被执行第二次，也会报同样的错。
**解法**：永远只保留一种安装方式。发生崩溃后，清空 `~/.dsh/profiles/desktop` 即可恢复（目录里会留下 `package.json.bak-*`、`cordis.patch.yml.bak-*` 之类的痕迹，属正常）。
**现状**：2026-11-05 回归测试确认已恢复健康——只有 1 份副本、bundles 里 1 条、无二次 `insert`，**无重复注册**。日志里那些报错是 11-04 的历史残留。

### 坑 2：硅基流动的"假参数"
不要试图加回 `batch_size`、`output_format` 或 `seed`。实测发现，服务端会返回 200，但**静默忽略**这些参数，加进去只会误导用户。

### 坑 3：余额必须 ≥ 0
虽然 Kolors 是免费模型，但接口依然会校验账户余额。如果余额小于 0，会报 HTTP 402（余额不足），无法出图。建议账户里放 1 块钱作为保证金。

### 坑 4：401 报错（Token is invalid）
一定、一定、一定要确保 API 请求是发往 **`https://api.siliconflow.cn`**（国内站）。如果发到国际站 `.com`，账号体系不互通，必报 401。

### 坑 5：Windows 文件夹迁移导致的"文件丢失"

本机曾把 Windows 用户目录（桌面、文档、图片）迁移到了 D 盘。这会带来两个真实后果：

1. **不要再去 `D:\Users\123` 找 DSH 数据** —— 那里确实有 `Desktop`/`Documents`/`Pictures` 等迁移过去的文件夹，但**没有 `.dsh`**。
2. DSH 的数据目录是 `C:\Users\123\.dsh`，它是 **Junction → `D:\Apps\DSHData`**。要找配置/账本，直接看 `D:\Apps\DSHData\dsh-api-free-image\`。

**2026-11-05 实证**：插件的 `config.json` 在迁移后**整份丢失**（自定义保存目录 + 卡片里存的 Key 一起没了），出图因此回落到默认的 `~\Pictures`。
恢复方式：用插件自己的接口重建，不要手写 JSON（会跳过目录可写性校验）——

```javascript
// 在任意已登录的 DSH 页面控制台里执行，或直接打开设置卡片点「更改保存位置」
fetch('/dsh-api-free-image/api/output-dir', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ outputDir: 'D:\\Pictures\\WorkBuddyImages' }),
})
```

> 关于备份：`D:\Users\123\_dsh-backup-20261019` 是 **2026-10-19** 的备份，早于 v1.1.0（11-04）安装，里面**没有**任何 Key / 用量数据，不能用来找回旧 Key。旧 Key 只能重新申请或重新填写。

## 五、npm 发布避坑（2026-11-05 一次踩穿）

> 这一节是「第一次发 npm」的完整血泪史。下次发新版本前，照着走即可。

### 坑 6：本机根本没有 npm
系统里**没有安装 Node.js/npm**，`npm` 命令直接不存在。但 DSH 自带运行时可以用：

```powershell
$node = 'D:\Apps\DSHData\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'   # v24.21.0
$pnpm = 'D:\Apps\DSHData\dsh-runtimes\dsh-primary-runtime\dependencies\pnpm\bin\pnpm.mjs'  # pnpm 11.28.5
```

**注意**：自带的 node 目录里只有 `node.exe`，**没有 npm.cmd / npm-cli.js**。所以一律用 pnpm 代替 npm。

发布命令（两个参数都不能省）：

```powershell
& $node $pnpm publish --access public --no-git-checks --ignore-scripts
```

- `--ignore-scripts`：`package.json` 的 `prepublishOnly` 是 `npm run build`，而本机没有 npm，不跳过会直接失败。**发布前务必先自己 build 好 `lib/`**。
- `--no-git-checks`：pnpm 默认要求干净分支、无未提交改动。

### 坑 7：2FA 导致 403（最坑的一个）
```
403 Forbidden
Two-factor authentication or granular access token with bypass 2fa enabled is required to publish packages.
```
账号开了 2FA 后，**普通 token 能通过 `whoami`，但没有发布权限**。必须去
<https://www.npmjs.com/settings/apfsds-dog/tokens> 新建 **Granular Access Token**，并且：

- Permissions：**Read and write**
- ✅ **勾选 `Bypass two-factor authentication (2FA)`** ← 成败关键
- **Packages and scopes：选 `All packages`**（新包还不存在，选具体包名会失败）

### 坑 8：token 少一位 → 401
经典 npm token 是 `npm_` + **36** 位，共 **40** 字符。少一位会返回**空响应体的 401**（不带 token 时返回的是 `{"error":"Unauthorized"}`，可据此区分）。
自查：`(Get-Content $env:USERPROFILE\.npmrc)` 数一下长度。
> 安全提醒：token 不要贴进聊天窗口。直接编辑 `C:\Users\123\.npmrc`：

```ini
registry=https://registry.npmjs.org/
//registry.npmjs.org/:_authToken=npm_你的完整token
```

### 坑 9：分阶段发布（staged publishing）会让页面出现 `0.0.0-stage`
首次发布会自动创建一个占位包：

```json
{ "name": "dsh-api-free-image", "version": "0.0.0-stage", "stub": true }
```

**这是 npm 服务端行为，不是发错了。** 真实版本会作为 staged release 提交，随后自动放行。两个典型表现：

- 刚发完查 registry，可能只看到 `0.0.0-stage`，`latest` 也不是你的版本 → **等 1 分钟左右 CDN 传播**；
- 立刻重试发布会报 `You cannot publish over the previously published versions: 1.1.0` → 说明上次**已经成功**，别再重试。

判断是否真成功，用带 `write=true` 的直连视图（会绕过 CDN 缓存）：

```
https://registry.npmjs.org/dsh-api-free-image?write=true&stage=1
```

占位版本 72 小时内可删（可选）：`npm unpublish dsh-api-free-image@0.0.0-stage`

## 六、核心验证脚本（不花额度）

- `check:request`：抓包自检，确认 Body 只有 4 个字段（`model`/`prompt`/`image_size`/`negative_prompt`），绝不包含假参数；同时验证并发记账不丢。
- `check:client`：服务端渲染自检，确认 UI 卡片（密码框、按钮、链接、标题）正常渲染。
- `typecheck` / `build`：类型检查与构建。

### ⚠️ 执行前置条件

1. **`node` / `pnpm` 不在系统 PATH 上**，直接敲会报 `无法将"node"项识别为 cmdlet`，必须用 §五 的绝对路径。
2. **`workspace-write` 文件策略下，任何命令都返回 `0xC0000142`**（进程初始化失败，连 `echo ok` 都挂）。
   这是 DSH 的 Windows 沙箱层故障，不是系统坏了、更不影响出图（出图走 host 进程）。
   临时解法：把会话切到 **完全权限 / danger-full-access** 后命令恢复正常（已实测 `PWSH_OK`）。
3. **即使命令能跑，`build.mjs` / `check-request.mjs` 仍可能报 `Error: spawn EPERM`**
   （2026-11-06 实测）：它们用 esbuild 子进程 / 起 node 子进程抓包，而沙箱禁止程序用管道打开子进程 stdio。
   这不是脚本坏了——切 `danger-full-access`（或给这一条命令放宽权限）就能过。
   `typecheck` / `check-client` 不需要子进程，普通权限下正常。

## 九、说明可收起（1.1.2 新增）

**要什么**：插件页那段「说明」是宿主（DSH）渲染的 README 长文，默认就摊在那里。阿昆要一个按钮把它收起来，而且**下次进来还收着**。

**怎么做**（改动很小，两半各一处）：

| 半 | 改了什么 |
|---|---|
| Client | 设置卡片标题行右侧（`✅ 已配置` 左边）加一个 ghost 按钮：`收起说明` / `显示说明`；点它给 `<html>` 加/去一个类 `kfi-hide-docs` |
| Client | 卡片自带 `<style>` 里加一条规则（见下），负责真正的隐藏 |
| Host | 新路由 `POST /dsh-api-free-image/api/ui-prefs`，body `{ hideDocs: boolean }`；`GET /status` 多返回一个 `ui: { hideDocs }` |
| 存储 | 写进同一份 `config.json` 的 `ui.hideDocs`（和 Key、保存位置同一个文件），所以重启 / 换端口 / 换会话都记得 |

真正隐藏说明的那条 CSS（**只隐藏紧挨着我们卡片的那一个说明块**，别的插件页不受影响）：

```css
html.kfi-hide-docs section[data-detail-document]:has(+ section[data-plugin-config] .kfi){display:none!important}
```

**为什么是这个选择器**：
- `section[data-detail-document]` 是 DSH 渲染 README 用的稳定 data 属性（在 `app.asar` 里搜这个字符串即可，出自 `ui-plugin-manager` 的 `PluginManagerPage` 与 `ui-primitives` 的 `DetailDocument`）；
- 宿主页面结构是 `.detailSections` 里依次放 `说明文档块` → `我们卡片所在的 section[data-plugin-config]`；
- 用 `:has(+ … .kfi)` 绑定「后面紧跟着的 config 区里确实有我们的卡片」，做到只影响本插件页。CSS 类名都是 hash 的（如 `V7pFBG_detailSections`），**不能拿类名当钩子**。

**已知边界**：
- 说明是宿主画的，插件 API 没有能往里插按钮的 slot。所以按钮在我们自己的卡片里（正好在说明块正下方），隐藏靠 CSS 作用在宿主的节点上。
- 因此 DSH 哪天改了 `data-detail-document` 或页面结构，这个开关会**静默失效**（说明重新出现，但按钮还在）。修法：在 asar 里搜 `data-detail-document` 重新对结构。
- 进页面到 status 返回之间有极短一瞬说明是展开的（本地几毫秒），不影响使用。
- **改了 host 半必须重启 DSH**：`dsh-unlag` 的刷新按钮只换了界面（client），后端还是旧的 → 点按钮会「瞬间收起又展开」（POST 失败后回滚），`GET /status` 也看不到 `ui` 字段。2026-11-06 现场踩过：判断办法就是看 `status` 里有没有 `ui`。
- 自检：`scripts/check-client.mjs` 覆盖按钮与文案；`ui-prefs` 路由用临时 `USERPROFILE` 起假 ctx 跑过一遍（200/400/405 + 落盘都验过）。

## 十一、发新版本的标准流程（照抄即可）

1. 改代码 → `tsc --noEmit` → `build.mjs` → 跑 `check-client` / `check-request`
2. 改 `package.json` 的 `version`（例如 1.1.1）
3. `pnpm pack` 生成新 tgz，本地 `remove` + `add` 验证一遍
4. `git add . && git commit -m "feat: ..."` → `git push`
5. `pnpm publish --access public --no-git-checks --ignore-scripts`
6. 等约 1 分钟，用 `?write=true&stage=1` 确认 `latest` 已是新版本
7. `git tag -f -a v1.1.1 -m "v1.1.1" main && git push -f origin v1.1.1`
